# Hands-free "Hey Claude" dictation into the terminal (WhisperWriter wake word)

## Context

terminal, with no Pause-key press. He wants it to work with his AirPods. Decisions he made:
- **Mic: toggle between laptop and AirPods** (tray switch). Holding the AirPods mic open puts them in
  Bluetooth hands-free mode, so audio sounds like a phone call while the listener is on. The toggle
  includes **Off**, which closes the AirPods mic and brings audio quality back.
- **Scope: terminal only.** The wake word only fires when Windows Terminal is the foreground window.

Run it once on the laptop mic and once on the AirPods mic during about 1 hour of normal work. Every

## Chunk 1: wake listener → dictation, laptop mic, terminal gate

**Recording ownership: one mic stream at a time, joined handoff.**
- New `src/wake_listener.py`: a `QThread` that runs openWakeWord on its own `sd.InputStream` and emits
  `wakeSignal(score)`.
  - `pause()` asks the thread to close its stream, then **blocks until the stream is closed**, using
    a `threading.Event` set after `stream.close()` returns. The wait times out after 2 s; a timeout
    aborts the new recording with a tray error, so two streams are never left open.
  - `resume()` reopens the stream. A failure to reopen is a tray error and leaves the listener stopped;
    it does not retry in a loop.
- **Every** recording, Pause-started or wake-started, calls `wake_listener.pause()` **before**
  `ResultThread.start()`. `resume()` is wired to `ResultThread.finished`, Qt's own signal. That signal
  fires on **every** exit path: success, `audio_data is None` (too short), exception, and `stop()`.
  Resume never depends on `resultSignal` (48b5c4f8b00f, 7b3e9f129464).

**Wake recordings always end on their own.**
- `ResultThread.__init__(local_model, source='key'|'wake', device=None)`. For `source='wake'`:
  - the mode is `voice_activity_detection`, whatever the global `recording_mode` says;
  - a **no-speech deadline** (`wake_options.no_speech_timeout_ms`, default 4000) ends the recording with
    no output when VAD never hears speech;
  - a **hard cap** (`wake_options.max_recording_s`, default 60) ends it regardless.
  A false wake followed by silence therefore ends in 4 s, types nothing, and the listener resumes
  (d711d13ba5bf, Codex P1).
- Pause-key recordings keep their current behavior (`hold_to_record`). The key path does not use the
  new deadlines.
- `main.py` tracks `self.recording_source`. `on_activation` and `on_deactivation` are **ignored while a
  wake recording runs**, so a Pause release cannot stop a wake recording, and a wake cannot start
  while a key recording runs (81558eb7d011).

**The terminal gate holds until typing.**
- New `src/foreground.py`:
  - `foreground_window()` → `GetForegroundWindow` HWND.
  - `process_name(hwnd)` → `GetWindowThreadProcessId` → PID → `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`
    → `QueryFullProcessImageNameW` → basename, closing the handle in `finally`.
  - **Fail closed:** a null HWND, a failed `OpenProcess`, or a failed query returns `None`, and `None`
    is never allowed (2f119d6b323a).
- On wake, `main.py` records the foreground HWND **and** checks its process name against
  `wake_options.allowed_processes`. If it doesn't match, it does nothing: no recording and no beep.
- Before typing a wake transcript, `main.py` checks that the **same HWND** is still foreground. If it
  isn't, the text is not typed anywhere. It is shown in a tray notification instead, so nothing is
  lost (8f119a4b2f8f, a0d354c03cd7).
- Text is **typed only and never auto-submitted**. Neill presses Enter.

**Config.**
- `config_schema.yaml` gets a new `wake_options` section using only types the settings window already
  renders (`bool`, `str`, `str`+options, `int`, `float`):
  - `enabled` (bool)
  - `wake_model` (str; deliberately not named `model_path`, a key the settings window special-cases)
  - `threshold` (float)
  - `allowed_processes` (str, comma-separated, default `WindowsTerminal.exe`)
  - `device` (str+options: `laptop|airpods|off`)
  - `airpods_match` (str, default `AirPods`)
  - `no_speech_timeout_ms` (int)
  - `max_recording_s` (int)
  (a675aae1d9dd)

**Tests (unittest).**
- Foreground: allowed, denied, null HWND, `OpenProcess` failure (stubbed ctypes) → denied.
- Same-HWND recheck: a focus change between wake and typing → no `typewrite`, tray message instead.
- `ResultThread` with `source='wake'`: a silent input ends at the no-speech deadline with no result;
  a constant-speech input ends at the hard cap.
- Handoff: `resume()` runs after the success, too-short, exception and stop exits (driven by
  `finished`). `pause()` returns only after the stream is closed.
- Key and wake isolation: Pause press and release during a wake recording are ignored.
- Wake detector on WAV fixtures: one wake clip, one negative clip; only the wake clip fires.

## Chunk 2: tray mic toggle (Laptop / AirPods / Off)
- Tray submenu "Mic: Laptop | AirPods | Wake off". The choice persists to `wake_options.device`.
- **One mic choice for both paths:**
  - Laptop: the wake listener and all dictation use the system default input (`sound_device: null`,
    today's behavior).
  - AirPods: the wake listener **and** Pause dictation use the resolved AirPods input.
  - Off: the wake listener's stream is closed (AirPods leave hands-free mode) and Pause dictation uses
    the system default input, exactly as today.

  `ResultThread` takes its device from this resolver, not from `recording_options.sound_device`
  directly (a737fc2aef48, e21d2503ac20).
- Resolver: from `sd.query_devices()`, keep only entries with `max_input_channels > 0` on the
  **WASAPI** host API (the one with full names; MME truncates them). Match `airpods_match` as a
  case-insensitive substring. It **never** matches by index, because Bluetooth indexes change on every
  reconnect. Observed 2026-10-16: the AirPods input is listed as `Headset (... Hands-Free ...;(AirPods Pro - Find My))`.
- AirPods selected but not found → switch to Off with a tray notification. Never fall back silently to
  another mic.
- Tests: the resolver against a recorded `query_devices()` fixture (output-only entries are ignored,
  only WASAPI entries match, and a missing device returns `None`, which leads to Off). The toggle sets
  the device for both paths.
