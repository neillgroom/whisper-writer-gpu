# Hands-free "Hey Claude" dictation into the terminal (WhisperWriter wake word)

## Context
Neill wants to talk to Claude Code hands-free: say a wake phrase, speak, and the text lands in the
terminal, with no Pause-key press. He wants it to work with his AirPods. Decisions he made:
- **Mic: toggle between laptop and AirPods** (tray switch). Holding the AirPods mic open puts them in
  Bluetooth hands-free mode, so audio sounds like a phone call while the listener is on. The toggle
  includes **Off**, which closes the AirPods mic and brings audio quality back.
- **Scope: terminal only.** The wake word only fires when Windows Terminal is the foreground window.

Current state (verified 2026-10-16): the live install is `C:\Tools\whisper-writer`. Its origin is
upstream savbell, and the GPU fixes sit there uncommitted. The maintained copy is the public fork
`github.com/neillgroom/whisper-writer-gpu`. In `config.yaml`: `activation_key: pause`,
`recording_mode: hold_to_record`, `sound_device: null`, `sample_rate: 16000`. `ResultThread._record_audio`
(`src/result_thread.py:119`) already runs WebRTC VAD stop-on-silence (900 ms) when the mode is
`voice_activity_detection`. It reads the mode from global config each time it records.

`origin/main` (12bbe00) matches the live install's `src/main.py` and `src/result_thread.py`, apart
from line endings. `main` has no `tests/` directory yet.

Two draft PRs from July (#1 and #2, "Helene" voice commands) sit unmerged on
`agent/windows-voice-control`. That branch adds a spoken-prefix command router: a transcript that starts
with "Helene" goes to a broker that launches apps and CLIs. This plan does not build on that branch or
touch it.

**Safety invariant:** the wake path is dictation-only. If #2 ever lands, wake-triggered transcripts must
never route to the command broker, because an always-on mic must not be able to launch anything.

Live process state (2026-10-16): **two** WhisperWriter instances are running, one from the venv and one
from system Python 3.11, and each has its own GPU worker. Two instances with a wake listener would mean
two listeners and double typing. Deploy must leave exactly one instance.

## Chunk 0: bounded test (no product code, scratch dir only)
Throwaway script: openWakeWord's **pre-trained `hey_jarvis`** model on a `sounddevice` stream.
Run it once on the laptop mic and once on the AirPods mic during about 1 hour of normal work.
- **Success:** at least 9 of 10 deliberate wakes detected, at most 1 false wake per hour, and the
  existing GPU stack still loads with the extra pins in a scratch venv (`numpy` must stay below 2).
- **Kill:** if either criterion fails after threshold tuning, drop the feature and report back. Do
  not expand the build to rescue it.
- New dependencies: `openwakeword` + `onnxruntime` (CPU). Both are free and local, with no account.

## Chunk 1: wake listener → dictation, laptop mic, terminal gate
- New `src/wake_listener.py`: a QThread that runs openWakeWord on its own input stream and emits
  `wakeSignal`. Its stream **closes while ResultThread records** and reopens afterward, so only one
  stream holds the mic at a time.
- New `src/foreground.py`: `is_allowed_foreground()` uses ctypes `GetForegroundWindow` →
  `GetWindowThreadProcessId` to get the process name. It checks that name against the config list
  `wake_options.allowed_processes`, which defaults to `WindowsTerminal.exe`.
- `ResultThread.__init__(..., mode_override=None)`: the wake path passes `voice_activity_detection`.
  The Pause key keeps `hold_to_record` unchanged. Edit `_record_audio` to use the override.
- `main.py`: `on_wake()` runs the gate check, then calls the existing `start_result_thread(mode_override=...)`.
  It does nothing when a recording is already running.
- Text is **typed only and never auto-submitted**. Neill presses Enter, so a misheard command can't
  run by itself.
- `config_schema.yaml`: new `wake_options` section (enabled, model path, threshold, allowed_processes, device).
- Tests (unittest): a stubbed foreground check covering allow and deny; `mode_override` selects the VAD path;
  the wake listener fed WAV fixtures (one wake clip, one negative clip) detects only the wake clip.

## Chunk 2: tray mic toggle (Laptop / AirPods / Wake off)
- Tray submenu "Wake listening: Laptop mic | AirPods | Off". The choice persists to `wake_options.device`.
- Devices are matched **by name substring** from `sd.query_devices()`, never by index, because
  Bluetooth device indexes change on every reconnect. Dictation uses the same device as the wake
  listener.
- If AirPods are selected but not connected, fall back to Off with a tray notification. Never fall
  back silently to a different mic.
- "Off" closes the stream entirely, which is what returns AirPods to full-quality audio.
- Tests: device resolution by name, including the missing-device path.

## Chunk 3: custom "Hey Claude" model
- Train `hey_claude.onnx` with openWakeWord's official training notebook. It uses synthetic speech,
  so no personal audio leaves the machine. Commit the model file and re-run the Chunk 0 criteria
  against it. Keep `hey_jarvis` as the config fallback.
